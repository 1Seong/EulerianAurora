# 맵 생성 재구축

기존 spine 생성, 기믹 사후 삽입, 전체 보드 템플릿, 포탈→인버터 전용 생성기는 제거했다. 새 상태 기반 생성기는 아직 미구현이며 후보 요청은 조건 검사 후 `GeneratorNotReady`를 반환한다.

## 입력과 계획

- `GenerationUiSettings`: 기믹 자동 여부·수동 허용 마스크, 난이도 자동 여부·수동 난이도만 관리한다. 개수나 필수 순서 필드는 없다. 자동일 때 보관된 수동 값은 검사와 적용에서 모두 제외한다.
- `GenerationConditions`: 백엔드에서 자연어를 해석하여 전달한 구조화된 조건이다. 허용 기믹, 난이도, 구체적 개수, 필수 기믹과 작동 순서를 담을 수 있다. 게임에는 자연어 파서가 없다. 백엔드 API 연결은 아직 미구현이다.
- `GenerationConditionResolver`: UI 제한과 추출 조건을 병합한다. 명시적 난이도 충돌, 금지 기믹 배치/필수 사용, 필수 기믹 0개, 잘못된 값, 예산 초과를 거절한다. 충돌을 임의로 덮어쓰지 않는다.
- `GenerationPlan`: 실제 선택된 난이도, 난이도가 자동 추첨되었는지, 유효 허용 범위, 필수 기믹/순서, 개수, 예산과 예약액을 불변 스냅샷으로 보관한다. `MapGenerationResult.Plan`으로 반환한다.

UI 기믹 자동은 자연어 조건을 해제하지 않는다. 자동에 자연어 조건도 없으면 모든 종류를 선택 후보로 허용한다. 수동에서 모든 종류를 해제하면 일반 길만 허용한다. 허용은 필수 등장을 뜻하지 않는다.

UI 난이도가 자동이고 자연어에 난이도가 있으면 그 난이도를 적용한다. 둘 다 미지정이면 최소 배치 비용을 감당하는 난이도 중 요청 seed로 추첨한다. 같은 seed/조건은 같은 결과를 낸다. 명시된 쉬움이 예산 부족이면 몰래 어려움으로 올리지 않고 실패를 알린다. 자동 난이도는 더 이상 보통으로 고정되지 않는다.

## 예산

| 종류 | 비용 | 쉬움 가중치 | 보통 가중치 | 어려움 가중치 |
|---|---:|---:|---:|---:|
| 일반 길 | 1 | 12 | 12 | 12 |
| 대시 | 2 | 5 | 5 | 5 |
| 포탈 쌍 | 3 | 5 | 5 | 5 |
| 레이저 | 4 | 3 | 3 | 3 |
| 고스트 | 5 | 1 | 3 | 6 |
| 회전 레이어 | 8 | 1 | 3 | 6 |
| 인버터 | 10 | 1 | 3 | 6 |

최대 풀은 쉬움 24 / 보통 45 / 어려움 80이다. 모두 조정용 초기값이며 실제 플레이 난이도를 보장하지 않는다. 솔버 탐색 상태 한도와도 별개다.

필수 기믹과 명시적 배치 개수의 최소 비용을 먼저 예약한다. 순서에 같은 기믹이 반복되어도 같은 배치의 재사용일 수 있으므로 중복 배치로 단정하지 않는다. 실제 생성 중 지출·되돌림, 마무리 여유 예산, 기믹별 공간 조건은 아직 미구현이다. 예산 검사를 통과해도 공간적으로 실현 가능하다는 뜻은 아니다.

## UI

- 기믹 자동/난이도 자동은 독립적이며 기본값은 자동이다. 개별 선택은 흐리게 비활성화하고 자동 해제 시 이전 값을 유지한다.
- 난이도는 쉬움/보통/어려움 중 하나만 선택한다. 기믹 개수 UI는 없다.
- 텍스트 없이 UI 설정만으로 요청할 수 있다. 백엔드 연결 전에는 텍스트 요청을 처리할 수 없다고 안내한다. 추후 백엔드 응답을 받으면 그 구조화된 조건과 로컬 UI 설정의 충돌을 검사한다.
- 보조 창은 1440×900 기준 우측에 340×460 크기로 배치한다. 상단 바 드래그로 이동할 수 있고 화면 경계에서 제한한다.
- 전체 화면 입력 차단용 배경은 완전히 투명하다. 맵을 어둡게 하거나 흐리게 하지 않는다.
- 다른 Canvas의 UI 오브젝트를 SetActive(false)로 숨기고 닫을 때 원래 activeSelf로 복원한다. 에디터와 보조 창이 들어 있는 공통 조상은 끄지 않고 UI 형제 가지를 숨긴다. 버튼 interactable 값은 변경하지 않는다.
- 긴 안내는 패널 내부에서 스크롤하여 버튼과 겹치지 않게 한다.

## 솔버와 남은 구현

기존 PuzzleSolver와 맵 저장 형식은 유지한다. MapAssistBridge의 Solve/Verify는 기존 클리어 탐색과 입력 재생을 사용한다. 이는 새 일반화된 기믹 작동 순서 검증과는 별개다.

다음은 생성용 시뮬레이션 경계 → 일반 이동·비인접 포탈 → 나머지 기믹의 상태 기반 배치 → 필수 작동 순서·클리어 마무리·최종 검증 순서다. 뒤의 배치가 이전 입력의 의미를 바꾸면 재생으로 거절해야 한다. AI API와 실행 중인 개발자용 게임에 연결하는 CLI/MCP는 후순위다.

## 검증

`dotnet run --project Tests/MapGeneration/MapGeneration.Tests.csproj`로 자동/수동 조건, 충돌, 예산, seed 재현성을 검사한다. 전체 게임 소스 컴파일과 Unity CLI 격리 UI 테스트도 수행한다. 격리 테스트에서는 오브젝트 숨김·복원, 투명 배경, 단일 난이도 선택, 작은 우측 배치, 드래그를 확인한다. 실제 게임 씬의 최종 머티리얼 외관은 별도로 확인해야 한다.

## 자연어 처리 경계

자연어 입력 → 백엔드 AI 해석 → 구조화된 MapAssistRequest 응답 → 로컬 UI 설정과 충돌 검사 → 생성·솔버 검증 순서다. 게임 내부의 정규식 파서와 입력창 JSON 해석은 제거했다. 데이터 계약은 MapAssistContracts.cs에 유지한다. MapTools.Generate는 이미 구조화된 요청을 받는 진입점이며 원문 텍스트를 해석하지 않는다. UiConditions는 로컬 전용이고 JsonIgnore로 백엔드 응답에서 분리한다. 실제 HTTP 호출, 응답 역직렬화와 오류 처리, 백엔드 API 스키마 확정은 이후 연결 단계에서 구현한다.
